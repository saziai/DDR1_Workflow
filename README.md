# DDR1 Computational Prioritization Workflow

Reproducible notebooks for DDR1 activity modeling, crystal-pose redocking, candidate docking, pose-quality assessment, PLIP interaction analysis, and figure generation.

**Status:** research workflow / candidate prioritization. Model predictions and docking scores are computational evidence only; they do not establish experimental DDR1 inhibition, selectivity, safety, or anti-keloid efficacy.

## Workflow overview

Run the notebooks in this order:

1. **`notebooks/0_DDR1_CONFIG.ipynb`** — creates/refreshes `ddr1_config.py` and initializes the shared directory layout.
2. **`notebooks/1_DDR1_MODEL.ipynb`** — audits and standardizes ChEMBL DDR1 activity records, trains and compares regression models, performs validation/diagnostics, and ranks DrugBank compounds.
3. **`notebooks/2_DDR1_REDOCK.ipynb`** — prepares the 5SB1 receptor and crystallographic reference ligand 1JI, derives the binding box, redocks with multiple seeds, performs atom-mapping QC and direct symmetry-corrected heavy-atom RMSD, and compares PLIP interactions.
4. **`notebooks/3_DDR1_DOCK.ipynb`** — consumes the model's candidate list and the receptor generated by Notebook 2; performs multi-seed candidate docking, pose reproducibility QC, representative-pose selection, complex generation, and optional PLIP analysis.
5. **`notebooks/4_DDR1_VIZ.ipynb`** — reads the candidate docking outputs and produces 2D/3D views, score plots, interaction heatmaps, JSON summaries, and an HTML gallery.

The intended root folder is named `DDR1_Workflow`. The shared configuration module centralizes the paths. In Google Colab, the notebooks use `/content/drive/MyDrive/DDR1_Workflow`; locally, they resolve the project root from the checked-out repository and its directory structure.

## Input files required

Place these files in `data/raw/` before running the workflow:

| File | Used for |
|---|---|
| `CHEMBL5319.xlsx` | ChEMBL-derived DDR1 activity records; expected columns include SMILES, standard activity type, and pChEMBL values. |
| `FDA_DrugBank_cleaned.xlsx` | Cleaned DrugBank compound table with names and SMILES. |
| `5SB1.pdb` | Crystal structure for the redocking workflow. |

These files are deliberately **not** included. Check source terms and permissions before distributing data. Notebook 2 stops if `5SB1.pdb` is missing. Notebook 1 requires the two spreadsheet inputs; Notebook 3 uses outputs from Notebooks 1 and 2.

## Environment

### Google Colab (recommended path in the notebooks)

The redocking and candidate-docking notebooks contain setup cells for installing the required tools, including AutoDock Vina and Python packages. Run the configuration notebook first, and make sure Google Drive is mounted when prompted. Installations may need to be repeated in a fresh Colab runtime.

### Local environment

A Conda environment specification is provided:

```bash
conda env create -f environment.yml
conda activate ddr1-workflow
```

Or install Python dependencies with:

```bash
python -m pip install -r requirements.txt
```

`requirements.txt` does **not** install the AutoDock Vina executable. Install Vina using your operating system's package manager and ensure `vina` is on `PATH`. PLIP's command-line executable must also be available for interaction analysis; the candidate notebook is designed to continue without PLIP and records that it was unavailable. Some packages (especially RDKit/ProDy) can be easier to install with Conda than with pip.

## Reproducibility and interpretation notes

- The notebooks record configuration, seeds, input/output paths, and file hashes where implemented. Keep the generated metadata and QC reports with the results for each run.
- Redocking RMSD is intended to be computed in the receptor coordinate frame without superposition. Symmetry correction changes atom correspondence, not pose coordinates. Review the atom-mapping audit and chemistry before interpreting RMSD.
- Docking scores are prioritization heuristics, not calibrated binding free energies or experimental potency measurements.
- The machine-learning target is derived from ChEMBL pChEMBL/IC50 records. Assay heterogeneity and the model's validation performance limit how quantitatively predictions should be interpreted.
- The candidate list is a ranking pool, not a set of confirmed inhibitors. Experimental biochemical validation is required.
- The notebooks are copied with saved cell outputs cleared to keep the public repository lightweight and avoid committing generated results. Re-run them to reproduce outputs.

## Creating the GitHub repository

1. Create a new **public** or **private** repository on GitHub named `DDR1_Workflow` (or another name if preferred).
2. Upload the contents of this folder or push them with Git.
3. Add the required input data locally / in Colab Drive; do not commit restricted datasets, large docking outputs, or credentials.
4. Before public release, review source-data permissions, verify all input provenance, and choose a repository license. No license file is included because the appropriate license has not been specified.
